# پنل مدیریت آموزش — نسخه اول

> وضعیت جدید: پنل پیش‌فرض مخفی و غیرفعال است. قبل از مراحل این راهنما، بخش فعال‌سازی در `MULTILINGUAL-STATUS.md` را بخوانید. گزارش پنل فعلی فقط مربوط به انگلیسی است.

## محدوده واقعی

این پنل فقط برای مدیریت آموزشی است. مسیر `/admin` برای مدیر و `/learning-access` برای رضایت و عضویت زبان‌آموز است. Runtime دستگاه در این دو مسیر نصب/اجرا نمی‌شود. برنامه قدیمی گوشی دوم و SQL عمومی دستگاه هنوز در پروژه وجود دارند؛ این تغییر آن‌ها را امن یا آماده انتشار عمومی نمی‌کند.

قابلیت‌ها: ورود ایمیل/رمز مدیر با نشست جدا از زبان‌آموز، فهرست اعضای دارای رضایت، جستجو و فیلتر، خلاصه درس و واژه‌های معرفی‌شده و زمان آموزشی، دعوت یک‌بارمصرف ۷روزه، لغو دعوت، توقف/ازسرگیری گزارش، لغو رضایت توسط زبان‌آموز، فهرست خواندنی محتوای فعلی. حالت نمایشی کاملاً برچسب‌گذاری شده و عملیات مدیریتی در آن غیرفعال است.

وجود داده نمونه در نمایشی به معنی اتصال سرور نیست. تعداد درس‌های کامل‌شده به معنی تسلط نیست؛ گزارش از داده دستگاه می‌آید و نباید مبنای امتحان رسمی یا پرداخت باشد. آخرین همگام‌سازی نشان‌دهنده «آنلاین بودن» فرد نیست.

موارد پیاده‌سازی‌نشده: قفل‌کردن خدمات/درس برای عضو تعلیق‌شده، محدودیت نصب APK، ویرایش و انتشار درس، اعلان عمومی، تکلیف، بازیابی حساب مهمان، MFA رابط پنل، محدودیت هزینه AI از این پنل و سابقه حسابرسی مدیریتی. توقف گزارش با قطع دسترسی به اپ فرق دارد. برای مدیریت حرفه‌ای توزیع اپ این موارد باید جدا طراحی و آزمون شوند.

## راه‌اندازی فقط با مرورگر

### ۱. آماده بودن جدول پیشرفت
پنل از جدول موجود learning_progress استفاده می‌کند. اگر قبلاً راه‌اندازی تولید را انجام داده‌اید، جدول باید موجود باشد. SQL دستگاه (SETUP-ALL-IN-ONE) را برای پنل اجرا نکنید؛ لازم نیست.

### ۲. نصب ساختار پنل
در Supabase → SQL Editor → New query، محتوای این فایل را کامل اجرا کنید:
`supabase/migrations/202610070001_education_admin.sql`
فایل تراکنشی است و می‌توان آن را دوباره اجرا کرد. جدول‌های اختصاصی education_admins، education_invites و education_enrollments ساخته می‌شوند. هیچ policy مربوط به پیام یا دستگاه تغییر نمی‌کند.

### ۳. ساخت حساب مدیر
در Authentication → Users → Add user، یک حساب ایمیل/رمز واقعی بسازید و وضعیت تأیید ایمیل را طبق امکانات داشبورد مشخص کنید. ایمیل و رمز متعلق به خودتان باشند. رمز را در چت یا Git قرار ندهید. حساب ناشناس فعلی زبان‌آموز را مدیر نکنید.

پس از ساخته‌شدن حساب، در SQL Editor قطعه زیر را اجرا کنید. فقط ایمیل و نام را با مقدار واقعی عوض کنید. اگر ایمیل شامل تک‌نقل‌قول است، آن را در SQL با دو تک‌نقل‌قول بنویسید. خروجی باید یک ردیف باشد؛ صفر ردیف یعنی حساب پیدا نشده یا ایمیل هنوز تأیید نشده است.

```sql
INSERT INTO public.education_admins (user_id, display_name)
SELECT id, 'مدیر آموزش'
FROM auth.users
WHERE lower(email) = lower('YOUR_ADMIN_EMAIL')
  AND email_confirmed_at IS NOT NULL
  AND is_anonymous IS NOT TRUE
ON CONFLICT (user_id) DO UPDATE SET display_name = EXCLUDED.display_name
RETURNING user_id, display_name;
```

عضویت مدیر فقط از SQL Editor/مسیر مورداعتماد سرور ممکن است؛ هیچ دکمه ثبت‌نام خودکار مدیر وجود ندارد. هرگز service_role را به کلاینت ندهید.

### ۴. ورود
مسیر `/admin` را در همان پیش‌نمایش باز کنید، یا در صفحه یادگیری «ورود مدیر آموزش» را بزنید. با حساب بالا وارد شوید. ذخیره نشست مدیر کلید مستقل `education-admin-session-v1` دارد و نشست زبان‌آموز را جایگزین نمی‌کند.

### ۵. آزمایش دعوت
از تب دعوت‌نامه‌ها یک دعوت بسازید. کد UUID بلند، یک‌بارمصرف و با اعتبار ۷ روز است و با کد شش‌رقمی مکالمه فرق دارد. کد دعوت محرمانه است؛ آن را فقط به شخص موردنظر بدهید. هر دارنده کد تا زمان مصرف/انقضا می‌تواند آن را بپذیرد؛ دعوت در این نسخه به ایمیل مشخص قفل نشده است.

زبان‌آموز در صفحه یادگیری «مدیریت اشتراک آموزشی» را باز می‌کند، کد را بررسی می‌کند، نام مدیر را می‌بیند و با نام نمایشی و رضایت صریح عضو می‌شود. پیشرفت قبلی همگام‌شده هم ممکن است نمایش داده شود؛ متن رضایت این موضوع را توضیح می‌دهد. برای دیدن تازه‌ترین گزارش، یک درس یا مرور را تکمیل کند و مدیر تازه‌سازی بزند. بدون همگام‌سازی موفق، داده محلی در پنل دیده نمی‌شود.

زبان‌آموز در همان صفحه می‌تواند رضایت را لغو کند. حذف عضویت دسترسی آینده مدیر را می‌گیرد؛ فایل یا تصویری که مدیر قبلاً ذخیره کرده قابل پس‌گرفتن نیست.

## مدل امنیتی

- education_admins: فقط SELECT ردیف خود برای authenticated؛ هیچ INSERT/UPDATE/DELETE کلاینتی ندارد.
- دعوت: فقط مدیر مالک می‌بیند/حذف می‌کند؛ INSERT کلاینت فقط روی ستون label مجاز است. مالک، کد و زمان انقضا در سرور تعیین می‌شوند.
- پذیرش دعوت: RPC با auth.uid، رضایت صریح، قفل ردیف، تاریخ انقضا و محدودیت یک‌بارمصرف.
- عضویت: زبان‌آموز فقط عضویت خود و مدیر فقط اعضای خودش را می‌بیند. کلاینت حق ساخت عضویت یا تغییر نام/رضایت ندارد.
- گزارش: RPC فقط خلاصه مجاز از اعضای همان مدیر برمی‌گرداند. دسترسی مستقیم عمومی/مدیریتی به learning_progress اضافه نشده است.
- توقف: summary و synced_at برای گزارش عضو paused حذف می‌شوند. داده خودِ زبان‌آموز پاک نمی‌شود.
- آموزش آفلاین همچنان در دسترس است؛ این نسخه DRM یا سیستم لایسنس نیست.

## آزمون

`npm run validate:admin` پایگاه PostgreSQL محلی موقت (PGlite) را می‌سازد و RLS، نقش‌ها، جداسازی مدیران، رضایت، لغو/انقضا/تکرار دعوت و محدودبودن گزارش را بررسی می‌کند. این آزمون به Supabase واقعی متصل نمی‌شود و جای آزمون دو مرورگر/دو حساب روی سرور واقعی را نمی‌گیرد.

`npm run typecheck` و `npm run validate:logic` و `npm run validate:content` نیز باید موفق باشند.

## پیش از انتشار عمومی

بهبود احراز هویت پایدار زبان‌آموز و بازیابی حساب، MFA مدیر، بررسی تمام سیاست‌های پروژه قدیمی، سیاست حریم خصوصی و نگهداری/حذف داده، نرخ‌دهی درخواست دعوت، حسابرسی و پایش، HTTPS و استقرار مستقل پنل، و آزمون واقعی با دو حساب لازم است. پیش‌نمایش Arena آدرس دائمی عمومی پنل نیست.
